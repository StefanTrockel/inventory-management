Data Flow — Filter to Render

User changes a filter
FilterBar.vue updates refs in the useFilters composable (warehouse, category, status, month/quarter).
View re-fetches
A watcher in the active view calls api.getInventory() / api.getOrders() etc., passing the current filters.
API client serialises params
client/src/api.js builds the query string via URLSearchParams, skipping any 'all' values.
FastAPI applies filters
apply_filters() and filter_by_month() in main.py narrow the in-memory list (quarters Q1-2025…Q4-2025 expand to their months).
Pydantic validates the response
Each endpoint declares a response_model so the JSON shape is guaranteed before it leaves the server.
Vue stores raw, derives computed
Raw arrays land in refs; derived values (totals, chart series, sort orders) live in computed properties so they recompute only when inputs change.
Template renders
Tables, custom SVG charts, and CSS Grid layouts re-render reactively — no manual DOM updates anywhere.

Notable Design Choices

Composition API everywhere
No Options API; refs + computed + composables for shared state.
Single shared filter set
Four filters apply consistently across all data-bearing views.
Custom SVG charts
No chart library — viewBox-scaled SVG keeps the bundle small.
No database
JSON files loaded once at startup; mutations are lost on restart.
Demo-only CORS
allow_origins=["*"] — suitable for local dev only.
Slate design system
Slate/gray palette, status colours (green/blue/yellow/red), no emojis in UI.
